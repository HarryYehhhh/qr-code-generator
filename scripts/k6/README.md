# k6 Load Test Scripts

This directory contains k6 load-test scripts for the QR Code Generator API.

## Prerequisites

- [k6](https://k6.io/docs/getting-started/installation/) installed locally, **or** Docker + Docker Compose.
- The full stack must be running before executing any scenario (except seed, which only needs the `api` service).

## Directory Structure

```
scripts/k6/
├── lib/
│   └── common.js        # Shared utilities: baseUrl(), buildThresholds(), pickToken(), loadTokens()
├── seed.js              # Pre-seed the DB with N tokens; outputs TOKEN: lines to stdout
├── redirect_hot.js      # Cache-hot redirect throughput benchmark
├── redirect_cold.js     # Cold-path (DB write + SETEX) latency benchmark
├── image_mixed.js       # 50/50 image cache hit/miss benchmark
├── tokens.json          # Generated by seed.js (git-ignored, create locally)
└── README.md            # This file
```

## Quick Start — Docker Compose (recommended)

```bash
# 1. Start the full stack (api, worker, redis, postgres, jaeger, prometheus, grafana)
docker-compose up -d

# 2. Seed tokens (run once; creates scripts/k6/tokens.json)
k6 run --env BASE_URL=http://localhost:8000 scripts/k6/seed.js \
  2>&1 | sed -nE 's|^time=.*level=info msg="TOKEN:([^"]+)".*|\1|p' | jq -R . | jq -s . > scripts/k6/tokens.json

# 3. Run a scenario (choose one):
k6 run --env BASE_URL=http://localhost:8000 scripts/k6/redirect_hot.js
k6 run --env BASE_URL=http://localhost:8000 scripts/k6/redirect_cold.js
k6 run --env BASE_URL=http://localhost:8000 scripts/k6/image_mixed.js
```

## Quick Start — k6 via Docker Compose loadtest profile

The `k6` service (profile `loadtest`) connects to the existing stack and pushes metrics to Prometheus via remote write.

```bash
# Start main stack first
docker-compose up -d

# Seed tokens
k6 run --env BASE_URL=http://localhost:8000 scripts/k6/seed.js \
  2>&1 | sed -nE 's|^time=.*level=info msg="TOKEN:([^"]+)".*|\1|p' | jq -R . | jq -s . > scripts/k6/tokens.json

# Run redirect_hot via docker-compose k6 service (default script)
docker-compose --profile loadtest run --rm k6

# Run a different script by overriding command:
docker-compose --profile loadtest run --rm k6 run /scripts/redirect_cold.js
docker-compose --profile loadtest run --rm k6 run /scripts/image_mixed.js
```

Prometheus scrapes k6 metrics at `http://localhost:9090`. Grafana is at `http://localhost:3000` (admin/admin).

## Scenarios

### seed.js

**Purpose**: Creates N QR code tokens in the database to pre-populate the token pool used by hot/cold redirect tests.

**Run**:
```bash
k6 run \
  --env BASE_URL=http://localhost:8000 \
  --env SEED_COUNT=1000 \
  scripts/k6/seed.js \
  2>&1 | sed -nE 's|^time=.*level=info msg="TOKEN:([^"]+)".*|\1|p' | jq -R . | jq -s . > scripts/k6/tokens.json
```

**Output**: `tokens.json` — an array of `qr_token` strings. Required by `redirect_hot.js` and `image_mixed.js`.

**Note**: `tokens.json` is read-only for k6 (`open()` is init-only). Tokens are printed with a `TOKEN:` prefix during the run; the shell pipeline above collects them.

---

### redirect_hot.js

**Purpose**: Measures cache-hot redirect throughput. All tokens are pre-loaded into Redis URL cache (via `POST /v1/qr_code`), so every `GET /r/{token}` hits Redis only — no DB queries.

**Stages**:
| Stage | Duration | VUs |
|-------|----------|-----|
| Warm-up | 30s | 0 → 50 |
| Steady | 2m | 200 |
| Spike | 30s | 500 |
| Ramp-down | 30s | 0 |

**Thresholds**: `p(99) < 500ms`, `error rate < 1%`

**Run**:
```bash
k6 run --env BASE_URL=http://localhost:8000 scripts/k6/redirect_hot.js
```

**Key metrics to watch**:
- Grafana: "Redirect QPS", "Redirect duration p50/p95/p99"
- Prometheus: `sum(rate(http_requests_total{handler="/r/{qr_token}"}[1m]))`
- Jaeger: trace `GET /r/{qr_token}` — Redis GET span should be <5ms

---

### redirect_cold.js

**Purpose**: Measures cold-path latency. Each VU creates a new token (Postgres INSERT) and immediately redirects, exercising `SHA-256 token generation → DB write → Redis SETEX → redirect`.

**Stages**: constant-vus, 50 VUs, 3 minutes.

**Thresholds**: `p(99) < 1500ms`, `error rate < 1%` (looser than hot path; Postgres write is the bottleneck)

**Run**:
```bash
k6 run --env BASE_URL=http://localhost:8000 scripts/k6/redirect_cold.js
```

**Key metrics to watch**:
- `docker stats db --no-stream` — expect DB CPU >50% under load
- Grafana: "qr_db_pool_in_use" — saturation at 3 causes queueing

---

### image_mixed.js

**Purpose**: Benchmarks QR image serving under 50% cache hit / 50% miss load. Cache hits use a fixed spec (same Redis key). Cache misses use randomised `dimension` / `color` / `border` parameters forcing PNG regeneration.

**Stages**:
| Stage | Duration | VUs |
|-------|----------|-----|
| Warm-up | 30s | 30 |
| Steady | 2m | 100 |
| Ramp-down | 30s | 0 |

**Thresholds**: `p(95) < 800ms`, `error rate < 1%`

**Run**:
```bash
k6 run --env BASE_URL=http://localhost:8000 scripts/k6/image_mixed.js
```

**Key metrics to watch**:
- `docker stats api --no-stream` — api CPU approaches 80-100% on cache miss
- Grafana: "Image cache hit rate" — expect ~50%
- Prometheus: `rate(qr_image_cache_total{result="hit"}[5m]) / rate(qr_image_cache_total[5m])`

## Filling the Performance Report

After running the scenarios, record results in [`docs/perf-report.md`](../../docs/perf-report.md). Each placeholder in that file has a `Source:` annotation pointing to the exact Prometheus query or Grafana panel.

**Recommended order**:
1. Start at baseline commit `6566794`: `git checkout 6566794 && docker-compose up -d --build`
2. Seed → run all 3 scenarios → fill "Baseline" columns in Section 3.
3. Switch to `main`: `git checkout main && docker-compose up -d --build`
4. Re-seed → run all 3 scenarios → fill "Current" columns + Section 2 tables.
5. Calculate Delta, write Bottleneck analysis and Conclusion.

Full step-by-step checklist is in `docs/perf-report.md` Section "How to fill this report".

## Prometheus Queries Reference

| Metric | Query |
| --- | --- |
| Redirect RPS | `sum(rate(http_requests_total{handler="/r/{qr_token}"}[1m]))` |
| Redirect p99 (ms) | `histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket{handler="/r/{qr_token}"}[1m])) by (le)) * 1000` |
| Image cache hit rate | `rate(qr_image_cache_total{result="hit"}[5m]) / rate(qr_image_cache_total[5m])` |
| DB pool in use | `qr_db_pool_in_use` |
| Click stream lag | `qr_click_stream_lag` |
| k6 RPS (requires remote write) | `sum(rate(k6_http_reqs[1m]))` |
| k6 p99 (requires remote write) | `k6_http_req_duration{quantile="0.99"}` |
